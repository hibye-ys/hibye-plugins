# 맡기기·고치기·재개

허가를 받고 일을 맡기거나, 카드·진행 표를 고치거나, 멈춘 일을 이어받을 때 읽는다.
일꾼을 어떻게 띄우고 살리는지는 프로젝트의 runtime을 따르고, 이 스킬은 그 방법을 정하지 않는다.

## 맡기기 전 확인

의존 과업이 받아들여졌는지 본다. 결과가 일꾼의 worktree에 없으면 맡기지 않는다.
같이 쓰는 파일·인터페이스·생성물·외부 자원을 함께 보고, 쓰는 곳이 겹치는 과업은 차례로 맡긴다. worktree를 따로 판다고 겹침이 없어지지 않는다.
커밋 안 한 변경을 worktree로 가져가면(예: "커밋 안 한 것도 가져가" 라고 할 때) 경로·가져간 방법·받은 쪽 확인을 카드에 적는다. 깨끗한 기준 commit에서 시작하면 이 줄을 빼도 된다.
쓸 수 있는 경로·모델·노력을 맡길 때 다시 확인한다. 카드에 적은 배정이 실제 호출의 증거가 아니다.

## 카드에 적는 것

고를 과업의 카드만 채운다. 스펙·계획 경로와 개정, 맡는 합격 조건, 고칠 범위, 입력, 끝난 것으로 보는 때, 돌릴 검증, 배정, 작업 위치를 쓴다.
일을 시작하기 전에 시작 상태를 적는다. 돌려받은 session id와 실행 경로를 적고, 모르는 id를 지어내지 않는다.
맡는 합격 조건이 바뀌면 카드가 무효가 되니 고쳐 맞출 때까지 맡기지 않는다. 상관없는 계획 고침은 끝난 일을 다시 돌리지 않는다.

## 일꾼에게 넘기는 것

카드·가리킬 원천·규칙과 함께 결과 계약을 분명히 말한다. 결과 계약은 카드의 지금 상태를 고치고, 상태·바뀐 경로·commit·확인 요약·안 풀린 것을 돌려주는 것이다.
계획 전체나 대화 전체를 보내지 않는다. 코드에 혼자가 아니니 남의 고침을 건드리지 말라고 말한다.
말로만 짧게 넘기면 이어받을 인계가 아니다. 카드에 계획 가리키기·작업 위치·배정·지금 상태·다음·근거가 있는지 보내기 전에 확인한다.

## 일하는 동안

뜻 있는 바뀜·확인 결과·막힘이 생기면, 그리고 주인에게 돌려주기 전에 카드의 지금 상태를 고쳐 쓴다. 예전 줄을 남긴 채 아래에 덧붙이지 않는다.
도구 호출 일지를 쓰지 않는다. 다시 일하지 않게 아직 필요한 결정·근거만 남기고, 긴 것은 링크한다.
운영에 닿는 명령처럼 위험한 것은 돌리기 전에 무엇을 하려는지 카드에 먼저 적고, 돌린 뒤 본 결과를 적는다. 모른다는 것은 실패가 아니다.
고치는 동안은 그 과업의 좁은 검증만 돌린다. 영향 범위의 전체 검증과 같이 쓰는 기록 고침은 마무리 과업에 맡긴다.

## 돌아온 결과 확인

일꾼이 "끝났다"고 말해도 그 말을 끝난 증거로 삼지 않는다. 맡긴 쪽이 diff를 보고 돌릴 검증을 직접 확인한 뒤에 카드의 상태를 바꾼다.
검증 근거에는 방법·환경·검사한 개정이나 커밋 안 한 입력 상태를 붙인다. 본 결과를 끝난 조건과 견준다.
실패·안 돌림·못 돌림이 하나라도 있으면 확인 필요에 둔다. 더 갈 수 없으면 막힘에 둔다. 끝내려고 합격을 낮추지 않는다.
합치기가 합격에 들면 합치고 영향 범위 검사가 맞을 때까지 확인 필요에 둔다. 일꾼의 worktree에서만 맞았다고 끝내지 않는다.

## 이어받기

status.md 머리부터 읽고, 지금 단계 카드의 지금 상태를 본 뒤 inject.md를 읽는다. 뜻이 비거나 어긋날 때만 spec·plan의 필요한 부분을 읽는다.
카드 말을 믿기 전에 git status·git log와 살아 있는 프로세스·session을 카드와 대조한다. 어긋나면 카드를 실제에 맞게 고치고 나서 이어 간다.
이어받으면 status.md 머리의 맡은 쪽을 자신으로 고친다. 남이 쥐고 진행 중인 일이면 가로채지 않고 사용자에게 묻는다.
가장 작은 남은 행동부터 간다. 끝난 과업과 이미 민 검증은 입력이 바뀌지 않으면 다시 하지 않는다.

## 마무리 과업

다른 과업이 다 받아들여진 뒤에 마무리 과업을 한다. 합치기·공통 검증을 한 번·기록 정리를 한다.
같이 쓰는 기록 파일은 마무리 과업에서만 고친다. 그래서 나란히 도는 과업이 기록 파일에서 부딪히지 않는다.
마무리가 끝나고 검사가 맞으면 PR을 올리고, 병합한 뒤 status.md의 상태를 끝남으로 바꾼다.
