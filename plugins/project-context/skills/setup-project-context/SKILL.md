---
name: setup-project-context
description: Set up or inspect project-context opt-in shared memory and lazy intent across Codex or Claude sessions, including linked Git worktrees.
---

Use the plugin repository's `scripts/setup-project.sh <project> --plugin project-context --tools codex,claude --preview` to preview the requested hosts, then apply the same command without `--preview` only within the user's setup request. `--check` reports pending configuration changes without writing. The installer owns host configuration merging and the byte-identical runner. See the plugin [README](../../README.md) for schema, CLI and support boundaries.

The project must choose its memory directory/index and/or existing intent directory in `.project-context.json`. Do not create or overwrite project memory or intent content as a setup side effect. No opt-in means no session injection. Memory resolves from Git's primary checkout; intent resolves from the current checkout. Independent clones have independent memory.

Rule skills such as `docs-boundary` are templates, not global skills. Only when the user asks for one, copy it with `node <plugin root>/scripts/skill-template.cjs install <skill> --project <project>`, where the plugin root is the installed cache `~/.claude/plugins/cache/hibye-plugins/project-context/<version>/` (Codex: `~/.codex/plugins/cache/hibye-plugins/project-context/<version>/`) or `plugins/project-context/` in a source checkout: it writes `.agents/skills/<skill>/SKILL.md` (the project's own copy, edited freely) and `.template-base.md` (merge base, never edited), and links `.claude/skills/<skill>` unless `.claude/skills` already points at `.agents/skills`. An existing copy is never overwritten; a rerun only re-checks the link. A `WARN:` line means an existing folder or link at `.claude/skills/<skill>` hides the copy from Claude: tell the user. `list` shows available templates.

Template update: shared rules change by editing `templates/skills/<skill>/SKILL.md` and raising its `metadata.template_version` together with the plugin version; an unversioned template edit does not propagate. When a copy's base is behind, SessionStart emits `SKILL_TEMPLATE_UPDATE <skill>` (opted-in projects only). Then run `status <skill>` and `diff <skill>` and show the shared change to the user; on their go-ahead run `update <skill>`, which merges base, project copy and new template three-way into the copy and moves the base forward. Conflicts stay in the copy as `<<<<<<< 프로젝트 / ||||||| 템플릿 vN / ======= / >>>>>>> 템플릿 vM` while the base stays put and the new template waits in `.template-pending.json`; resolve them with the user and run `update` again to raise the base (`update` refuses while markers remain; a copy reverted to its pre-merge content is merged again instead), then commit the copy, base and any pending file together.

Verify `doctor`, the host's enabled user snapshot and all four SessionStart events. Codex emits a lazy index pointer; Claude's native `autoMemoryDirectory` owns the index load, so the hook emits no index text. Preserve unrelated hooks and settings. Source links are development artifacts and cannot satisfy the installed snapshot contract. A failure marker is not a successful initialization; fix its cause before claiming acceptance. Muse/Antigravity adapters are source-only until product acceptance is independently demonstrated.
