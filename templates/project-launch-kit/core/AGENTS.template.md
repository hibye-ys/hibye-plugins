# AGENTS.md — {{PROJECT_NAME}}

이 파일은 저장소 전체에서 에이전트와 개발자가 반복해서 따라야 할 **짧고 안정적인 실행 규칙**만 담는다.
제품 가설·현재 작업·시스템 구조를 여기에 복사하지 않고 아래 정본을 필요한 범위만 읽는다.

## 1. 적용 범위와 우선순위

- 이 파일은 저장소 전체에 적용한다.
- 하위 디렉터리의 `AGENTS.md`는 그 경로의 고유한 규칙만 추가한다.
- 더 구체적인 규칙은 해당 경로에서 우선하지만, 루트의 안전·권한 경계를 조용히 약화하지 않는다.
- 규칙 충돌이나 적용 범위가 불명확하면 변경 전에 소유자에게 알린다.

## 2. 작업 전에 찾을 정본

| 필요한 정보 | 읽을 곳 |
| --- | --- |
| 현재 제품 가설·범위·중단 조건 | `PROJECT_BRIEF.md` |
| 활성 작업·owner·미해결 결정 | `STATE.md` |
| 모듈·데이터·외부 시스템 경계 | `SYSTEM_MAP.md`가 존재할 때 |
| 중요한 결정의 이유와 재검토 조건 | `docs/decisions/` |
| 변경 시 함께 움직이는 정본·파생물 | `docs/operations/coupling-map.md`가 존재할 때 |
| 검증 명령과 통과 시점 | `ops/gate-registry.yaml`이 존재할 때 |
| 재발 방지 교훈 | `docs/lessons/README.md`가 존재할 때 |

- 문서 주장보다 현재 구현, 실제 호출 경로, 테스트 결과, 외부 시스템 readback을 우선한다.
- 같은 사실을 여러 파일에 손으로 복사하지 않는다. 파생 가능하면 정본에서 생성한다.

## 3. 결정 권한

### 작업 범위 안에서 자율적으로 결정할 수 있다

- 요청을 구현하기 위한 국소적이고 되돌릴 수 있는 코드 구조
- 변경된 계약을 판별하는 가장 작고 결정적인 검증
- 기존 경계를 보존하는 내부 정리와 명백한 결함 수정

### 소유자의 명시적 결정이 필요하다

- 제품 범위·사용자 경험·디자인 방향·가격·정책 변경
- 공개 API·데이터 보존·호환성·권한 경계를 바꾸는 결정
- 운영 mutation, secret·credential 변경, 결제 또는 외부 게시
- 데이터 삭제·복구처럼 파괴적이거나 되돌리기 어려운 작업
- {{PROJECT_SPECIFIC_APPROVAL_BOUNDARY}}

결정되지 않은 값을 구현 편의를 위해 추측하지 않는다. `UNDECIDED`로 남기고 `STATE.md`에 연결한다.

## 4. 작업공간과 변경 안전

- 기존 dirty 변경과 사용자 작업을 보존하고 요청과 무관한 파일을 수정하지 않는다.
- 삭제·덮어쓰기 전에 정확한 대상과 복구 가능성을 확인한다.
- 검증 게이트를 숨겨서 우회하거나 실패를 성공으로 보고하지 않는다.
- secret·credential·개인정보·운영 데이터를 저장소나 로그에 기록하지 않는다.
- fallback·legacy 경로·새 추상화는 명시된 요구나 실제 반복 근거 없이 추가하지 않는다.
- 병렬 작업은 파일 소유권을 나누고, 같은 파일을 동시에 편집해야 하면 별도 branch·worktree를 사용한다.

## 6. 검증 원칙

- 변경된 계약과 가장 큰 위험을 먼저 식별한다.
- 그 위험을 판별하는 가장 작고 결정적인 검사부터 실행한다.
- 좁은 검사로 결론을 낼 수 없거나 영향이 넓으면 통합·전체 검증으로 확대한다.
- 검사하지 않은 범위, skip, 환경 실패, 제품 실패를 구분해 그대로 보고한다.
- 게이트가 생긴 뒤 실제 명령과 실행 시점은 `ops/gate-registry.yaml`을 따른다.

- [ ] 미확인 위험과 후속 결정이 `STATE.md`에 남음
- [ ] 정본·파생물·실제 구현이 서로 충돌하지 않음
- [ ] 실행하지 않은 검증과 남은 위험이 최종 보고에 포함됨
